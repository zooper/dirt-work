# Decisions

- 2026-11-11: Godot 4 + GDScript selected for a Linux SSH/headless workflow and macOS prototype.
- 2026-11-11: Low-poly Nordic quarry chosen as first environment.
- 2026-11-11: Xbox is a future possibility; no assumption of direct Godot console export.
- 2026-11-11: Simplified gravel volume model chosen over per-stone rigid-body simulation for MVP.
- 2026-11-11: Linux dev host pinned to official Godot 4.3-stable (SHA512-verified), matching CI image barichello/godot-ci:4.3.
- 2026-11-11: Wheel loader uses a kinematic CharacterBody3D with center-articulated steering kinematics instead of VehicleBody3D/RigidBody wheels: predictable, easy to tune, cheap. Revisit if suspension feel demands it.
- 2026-11-11: Loader simulation (`WheelLoader`) is input-agnostic; `PlayerLoaderInput` maps InputMap actions onto it so tests/AI can drive it directly.
- 2026-11-11: Bucket is self-levelling (approximates parallel Z-bar linkage); tilt is relative to level, not to the arms. Bucket/arms have no world collision in M1.
- 2026-11-11: Chassis pitch/roll to the floor is visual only; collision stays upright.
- 2026-11-11: Quarry is a seeded procedural blockout from primitives (no external assets). Gravel piles are drivable convex hulls without volume accounting until M2.
- 2026-11-11: Art direction targets the user's concept image: saturated golden-hour palette, faceted angular rock benches, dense pine plateau, lake and snow-capped mountains. Colours live in `scripts/world/palette.gd`.
- 2026-11-11: Static scenery is merged into vertex-coloured, flat-shaded `LowPolyBatch` meshes (one draw call per batch); trees and rubble use MultiMesh. Keeps the Compatibility renderer fast on a modest Mac.
- 2026-11-11: Presentation-only world scripts live in `scripts/world/` (palette, batch builder, quarry world, site props), separate from gameplay logic.
- 2026-11-11: Machine model designations are fictional (`DW-90`); real manufacturer model names from the concept art are not used.
- 2026-11-11: The Linux host cannot render (no display), so visuals are reviewed from macOS screenshots (F12 / gamepad View → user://screenshots).
- 2026-11-11: `tests/check.sh` is the single validation entry point and fails on any engine/script error, except the known dummy-renderer `Parameter "m" is null` message caused by Label3D in headless mode.
- 2026-11-11: Visual review loop on the Linux host: a locally unpacked Xvfb + Mesa llvmpipe renders the real Compatibility renderer; `tools/capture_shots.gd` writes fixed camera shots (play / concept hero / overview). Forward+ on lavapipe crashed in Godot 4.3, so the project stays on Compatibility for now.
- 2026-11-11: Bug fixed: hand-written `.tscn` Transform3D values were column-major; Godot's text format is row-major. Rotated nodes (incl. the sun, which shone upward) were inverted.
- 2026-11-11: Godot 4.3 Compatibility treats albedo/vertex colours as linear (everything looked pale). All colours go through `Palette.render()`, which linearizes only when no RenderingDevice exists (= Compatibility). Palette values are therefore true sRGB design colours. The loader scene is generated by `tools/gen_wheel_loader.py` with the same conversion.
- 2026-11-11: Loader visual wheel radius raised to 1.0 m (frames lifted 0.2 m); physics shapes unchanged.
- 2026-11-11: Default controls follow Farming Simulator conventions (WASD, J/N arm, K/M tool, mouse look, C camera, 1/2/3 cruise; gamepad RT/LT, LB + right stick for the loader). Source for the keyboard loader keys: community transcriptions of the FS manual/guides; gamepad loader mapping is our own choice because no authoritative default was found.
- 2026-11-11: Articulation bends both frames by half the angle around the hinge; the body heading is the bisector and the hinge moves along the front frame heading.
- 2026-11-11: Loader rebuilt from procedural bevelled parts (ChamferBox, FenderArch, BucketShell) generated by tools/gen_wheel_loader.py.
- 2026-11-11: Renderer switched to Forward+ (target: Apple Silicon Macs) for SSAO, SSIL, glow, ACES tonemapping and soft shadows. Palette.render() stops linearizing automatically (RenderingDevice present). Server previews (`tools/render_preview.sh`) use the Mobile renderer on Mesa lavapipe with fog disabled, because Godot 4.3 Forward+ and fog crash on lavapipe; previews therefore lack SSAO/SSIL/fog.
- 2026-11-11: Machine models are authored in code with Blender 4.2 LTS (`tools/blender/build_wheel_loader.py`, official build, SHA256-verified) and exported as glTF parts to `assets/models/wheel_loader/`. The .glb files (~560 KB total) are committed because Godot/CI need them and CI has no Blender; regenerate them with the script rather than editing by hand. Provenance: 100% generated by our script, no external meshes or textures.
- 2026-11-11: Visual passes follow docs/ART_DIRECTION.md: before/after review shots (JPEG) and notes live in docs/reviews/<date>-<topic>/. Pass 1 rebuilt the DW-90 rear body (integrated counterweight, flared fender shells, framed grille).
- 2026-11-11: The DW-40 hauler is a parked StaticBody3D prop (Blender-built) used as the loading target until M2 adds volume accounting; it may become drivable later.
- 2026-11-11: `WheelLoader.bucket_fill` is a presentation hook (bucket heap + pour/dust via `BucketSpill`, CPUParticles3D for renderer independence); gameplay will drive it in M2.
- 2026-11-11: Sun comes from the south-east so the showcase loading bay is front-lit like the reference; gameplay chase camera gets side light.
